## 2026-09-08T06:03:08Z Scope expanded to three additional features

### Claims

- [settled] original-feature-list-confirmed: The assignment offers crash-safe resume, safe retries, concurrent workers, graceful drain, observability, and adaptive backoff; crash-safe resume is mandatory and at least one other feature is required.
- [settled] baseline-feature-count: Crashsafe currently implements crash-safe resume, safe retries, graceful drain, and an append-only history supporting audit; it does not yet implement leased concurrency, a timeline view, or tool-wide adaptive throttling.
- [settled] extension-plan-added: Phases 10–13 of `.memory/projections/plans/crashsafe-engine.md` now cover concurrent workers, adaptive backoff, observability, integrated tests, README updates, and replacement demos.

### Commitments

- [accepted] two-worker-demo: Keep one worker as the default, make the count configurable, and run two in the concurrency and crash-recovery demos.
- [accepted] workflow-lease-granularity: Lease an entire workflow rather than an individual step so two workers cannot validly advance different steps of the same run.
- [accepted] fencing-required: Lease expiry alone is insufficient; every worker-originated transition must validate a monotonic fence token so a resumed stale worker cannot commit.
- [accepted] renewable-in-flight-lease: Renew while synchronous tool I/O is active; on graceful drain, finish and commit the current attempt, release ownership, and admit no new workflow.
- [accepted] shared-adaptive-throttle: Treat the mock service as one `tool_key`; a 429 extends a persisted maximum cooldown that gates other workflows across all workers.
- [accepted] timeline-demo-output: Derive a readable sequence/relative-time/step/attempt/worker/wait/outcome timeline from history and print it at the end of the demo.

### Non-goals retained

- No distributed shards, remote consensus, generalized task queue, fan-out, arbitrary DAGs, graphical UI, tracing backend, or token-bucket rate controller.
- The concurrency claim is one valid committing lease owner per workflow, not exactly-once compute or exactly-once external execution.
